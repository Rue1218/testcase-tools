# 功能测试用例标准

> 本标准用于增强业务需求、功能说明类文档的测试用例覆盖。

---

## 一、适用范围

- 业务需求文档（BRD）
- 功能需求规格说明书（FRS）
- 产品需求文档（PRD）
- 用户故事（User Story）

---

## 二、通用测试策略

### 2.1 业务流程测试

每个业务流程至少覆盖：
- **主流程**：正常业务操作的完整路径
- **分支流程**：条件分支的处理路径
- **异常流程**：业务规则校验失败的路径

### 2.2 状态流转测试

状态机相关的功能需覆盖：
- **合法状态迁移**：每个允许的状态转换路径
- **非法状态迁移**：未定义的状态转换是否被正确拒绝
- **初始状态**：系统启动时的默认状态
- **终止状态**：业务操作的终态

### 2.3 角色与权限测试

涉及多角色的功能需覆盖：

| 测试类型 | 说明 |
|---------|------|
| 角色权限正集 | 功能对应的角色应能正常访问 |
| 角色权限负集 | 无权限的角色应被拒绝访问 |
| 权限组合 | 多个权限组合的场景 |
| 权限继承 | 角色权限的继承关系 |
| 超级管理员 | 特殊角色的权限覆盖 |

### 2.4 数据约束测试

- 必填项校验
- 数据格式校验（日期、邮箱、手机号等）
- 数据长度校验（最大/最小）
- 数据范围校验（数值区间）
- 唯一性校验
- 业务规则校验

---

## 三、用例命名规范

```
【类型】业务动作_验证点_[条件]

示例：
【正向】用户登录_用户名密码正确_登录成功
【反向】用户登录_密码错误_提示密码错误
【边界】用户注册_用户名长度刚好33字符_提示过长
【状态】订单_已支付取消订单_状态变为已取消
```

---

## 四、用例结构模板

### 4.1 标准用例格式

```
前置条件：XXX
步骤：
  1. 执行XXX操作
  2. 输入XXX
  3. 点击XXX
预期结果：
  1. 系统显示XXX
  2. XXX状态变为XXX
```

### 4.2 场景用例格式

```
场景：XXX业务场景

背景（可选）：
  - 当前用户：XXX
  - 当前时间：XXX
  - 系统状态：XXX

流程：
  1. XXX → 结果：XXX
  2. XXX → 结果：XXX
  3. XXX → 结果：XXX

预期：
  - 最终状态：XXX
  - 输出数据：XXX
  - 通知消息：XXX
```

## 五、用例数量估算

| 复杂度 | 功能模块数 | 状态数 | 用例估算 |
|--------|-----------|--------|---------|
| 简单 | 1-3 | 0-2 | 15-30 |
| 中等 | 4-7 | 3-5 | 30-60 |
| 复杂 | 8+ | 6+ | 60-120 |

---

## 六、质量检查清单

- [ ] 主业务流程是否覆盖完整链路
- [ ] 分支流程是否覆盖所有条件分支
- [ ] 非法状态迁移是否有用例覆盖
- [ ] 各角色的权限边界是否清晰
- [ ] 必填项和格式校验是否完整
- [ ] 边界值是否有对应用例
- [ ] 数据唯一性约束是否验证
- [ ] 典型用户场景是否覆盖
