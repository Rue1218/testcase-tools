# 接口测试用例标准

> 本标准用于增强接口说明、API文档类文档的测试用例覆盖。

---

## 一、适用范围

- REST API 文档
- GraphQL 接口
- WebService 接口
- 内部微服务接口
- 第三方 API 集成

---

## 二、通用测试策略

### 2.1 参数校验测试

| 校验类型 | 测试点 |
|---------|--------|
| 必填参数 | 缺失必填参数、参数为空 |
| 参数类型 | 类型错误（字符串传数字） |
| 参数格式 | 格式不符合规范（日期、邮箱） |
| 参数长度 | 超长、超短、刚好临界值 |
| 参数范围 | 超出有效范围、边界值 |
| 枚举值 | 不在枚举列表中的值 |
| 重复参数 | 相同key多次出现 |

### 2.2 请求方法测试

| 方法 | 测试点 |
|-----|--------|
| GET | 查询操作、参数拼接、缓存行为 |
| POST | 创建资源、请求体构造 |
| PUT | 全量更新、幂等性验证 |
| PATCH | 部分更新、字段处理 |
| DELETE | 删除操作、重复删除 |

### 2.3 鉴权与授权测试

| 测试类型 | 说明 |
|---------|------|
| 无鉴权 | 未携带Token/Session |
| Token无效 | 过期Token、格式错误、伪造Token |
| Token正确 | 正常鉴权流程 |
| 权限不足 | 低权限用户访问高权限接口 |
| 跨租户 | A租户访问B租户资源 |

### 2.4 业务逻辑测试

- 数据创建是否符合预期
- 数据查询返回是否完整
- 数据更新的原子性
- 数据删除的级联影响
- 并发操作的数据一致性

### 2.5 错误码测试

每个接口的所有错误码都需要覆盖：

```
错误码格式：XXX-XXX-XXXX
示例：USER-AUTH-0001

测试点：
- 每个错误码是否可触发
- 错误响应格式是否一致
- 错误消息是否清晰可理解
```

## 三、特殊场景测试

### 3.1 幂等性测试

| 接口类型 | 幂等性要求 |
|---------|-----------|
| GET | 天然幂等 |
| PUT | 多次调用结果相同 |
| DELETE | 重复删除返回相同结果 |
| POST | 通常非幂等，需特殊处理 |

### 3.2 并发测试

- 多线程同时请求同一接口
- 分布式环境下的并发调用
- 并发修改同一数据的冲突处理

### 3.3 事务测试（批量接口）

- 全部成功场景
- 部分成功部分失败
- 全部失败场景
- 事务回滚验证

### 3.4 异步接口测试

- 任务提交成功
- 任务状态查询
- 任务结果获取
- 任务超时处理
- 任务失败重试

## 四、用例命名规范

```
【类型】HTTP方法_资源_操作_[条件]

示例：
【正向】POST_user_create_正常创建用户
【反向】POST_user_create_用户名已存在_409
【边界】GET_user_list_page=0_返回第一页
【异常】GET_user_id=999_资源不存在_404
【鉴权】POST_order_create_未带Token_401
```

## 五、用例结构模板

### 5.1 标准接口用例

```
接口：XXX
URL：/api/xxx
方法：GET/POST/PUT/DELETE

请求参数：
  - header: Authorization: Bearer xxx
  - query: page=1&size=10
  - body: {"name": "xxx"}

前置条件：XXX
步骤：
  1. 发送GET请求到 /api/xxx
  2. 携带请求头XXX
预期结果：
  1. HTTP状态码：200
  2. 响应体包含：data, total
  3. 响应时间 < 200ms
```

### 5.2 错误码用例

```
接口：XXX
错误码：AUTH-001
触发条件：Token过期

前置条件：Token已过期
步骤：
  1. 携带过期Token请求接口
预期结果：
  1. HTTP状态码：401
  2. 响应体：{"code": "AUTH-001", "message": "Token已过期"}
```

## 六、用例数量估算

| 接口复杂度 | 参数数 | 错误码数 | 用例估算 |
|-----------|--------|---------|---------|
| 简单 | 1-3 | 1-3 | 10-20 |
| 中等 | 4-7 | 4-6 | 20-40 |
| 复杂 | 8+ | 7+ | 40-80 |

## 七、质量检查清单

- [ ] 必填参数缺失是否都有覆盖
- [ ] 参数类型错误是否覆盖
- [ ] 参数格式校验是否完整
- [ ] 长度/范围边界值是否覆盖
- [ ] 所有错误码是否可触发
- [ ] 鉴权失败场景是否覆盖
- [ ] 权限不足场景是否覆盖
- [ ] 幂等性是否验证（适用于PUT/DELETE）
- [ ] 并发场景是否有覆盖
- [ ] 响应时间是否符合要求
