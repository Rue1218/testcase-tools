# testcase-tools

根据 PRD、需求文档、接口文档自动生成测试用例的 Claude Code Skill。支持输出 **XMind 思维导图**和 **Excel 测试用例**两种格式，也支持 Excel 与 XMind 之间的格式互转。

## 功能特性

### 核心能力

- **多格式输入**：PRD、需求文档、接口文档（OpenAPI/Swagger）、Excel 测试用例
- **多格式输出**：XMind 思维导图（.xmind）和 Excel 测试用例（.xlsx）
- **格式互转**：Excel 与 XMind 双向转换
- **智能生成**：运用六大测试策略自动生成用例
- **优先级标记**：P0/P1/P2/P3 四级优先级，带颜色区分

### 测试策略覆盖

| 策略 | 说明 |
|------|------|
| 正向测试 | 正常流程验证，每个核心功能至少 1 条 |
| 反向测试 | 异常/负向用例，验证系统正确拒绝非法输入 |
| 边界值测试 | 最小值、最大值、空值、临界点 |
| 等价类划分 | 有效/无效等价类，每类选取代表值 |
| 状态流转测试 | 合法/非法状态迁移 |
| 场景测试 | 端到端用户故事，跨模块串联 |

## 安装

### 方式一：全局安装（推荐）

```bash
git clone https://github.com/Rue1218/testcase-tools.git ~/.claude/skills/testcase-tools
```

### 方式二：项目级安装

```bash
mkdir -p .claude/skills
git clone https://github.com/Rue1218/testcase-tools.git .claude/skills/testcase-tools
```

安装后重新启动 Claude Code 会话即可使用。

## 使用方式

在 Claude Code 中输入以下任意指令触发：

| 指令 | 说明 |
|------|------|
| `根据这份 PRD 生成测试用例 XMind` | PRD 转 XMind |
| `把接口文档转成测试用例 Excel` | 接口文档转 Excel |
| `Swagger/OpenAPI 转测试用例` | Swagger 格式转测试用例 |
| `测试用例 Excel 和 XMind 互转` | 双向格式转换 |
| `.xmind 测试用例文件转 Excel` | XMind 转 Excel |

## 输入格式

### PRD / 需求文档

直接粘贴 PRD 或需求说明文本，支持：
- 产品需求文档（PRD）
- 功能需求规格说明书（FRS）
- 业务需求文档（BRD）
- 用户故事（User Story）

### 接口文档

支持以下格式：
- OpenAPI / Swagger（JSON 或 YAML）
- Markdown 格式的接口说明
- Postman Collection
- 自定义格式的接口列表

### Excel 测试用例

上传 `.xlsx` 文件，支持标准列结构：

```
用例编号 | 模块 | 用例名称 | 优先级 | 用例类型 | 前置条件 | 测试步骤 | 预期结果
```

也支持简化格式：`模块 | 用例名称 | 步骤 | 预期`

## 输出格式

### XMind 格式

生成 `.xmind` 文件，结构如下：

```
根节点：项目名称
├── 一级节点：功能模块
│   ├── 二级节点：子功能点
│   │   ├── 三级节点：【正向】用例名称-P0
│   │   ├── 三级节点：【反向】用例名称-P1
│   │   └── 三级节点：【边界】用例名称-P2
```

**优先级标记**：

| 标记 | XMind 标记 | 说明 |
|------|-----------|------|
| P0 | priority-1（红星） | 核心用例，必须通过 |
| P1 | priority-2（橙星） | 重要用例，建议通过 |
| P2 | priority-3（黄星） | 普通用例，常规覆盖 |
| P3 | priority-4（绿星） | 低优先级，可选覆盖 |

**用例类型标记**：

| 标记 | 含义 |
|------|------|
| 【正向】 | 正常流程用例 |
| 【反向】 | 异常/负向用例 |
| 【边界】 | 边界值用例 |
| 【等价】 | 等价类用例 |
| 【状态】 | 状态流转用例 |
| 【场景】 | 端到端场景用例 |

### Excel 格式

| 列名 | 必填 | 说明 |
|-----|------|------|
| 用例编号 | 是 | 唯一标识，格式 TC-XXX |
| 所属模块 | 是 | 功能模块名称 |
| 用例标题 | 是 | 清晰表达验证点 |
| 优先级 | 是 | P0/P1/P2/P3 |
| 用例类型 | 是 | 功能测试/边界测试/异常测试等 |
| 前置条件 | 否 | 执行前提条件 |
| 测试步骤 | 是 | 1.2.3. 步骤描述 |
| 预期结果 | 是 | 预期输出/响应 |

Excel 输出带优先级颜色区分（P0 红、P1 橙、P2 黄、P3 绿）和自动筛选器。

## 参考标准

`references/` 目录包含四份测试用例设计标准文档，Skill 会根据输入文档类型自动叠加对应标准：

| 文档类型 | 参考标准 | 增强内容 |
|---------|---------|---------|
| 功能需求 | `functional-testcases-standard.md` | 业务流程、状态流转、角色权限 |
| 接口文档 | `api-testcases-standard.md` | 请求参数校验、错误码、鉴权、幂等 |
| 性能需求 | `performance-testcases-standard.md` | RT、QPS、吞吐量、稳态/峰值 |
| 自动化候选 | `automation-testcases-standard.md` | 标记自动化适用性 |

## 用例数量估算

### PRD / 需求文档

| 模块复杂度 | 正向 | 反向 | 边界 | 状态/场景 |
|-----------|------|------|------|----------|
| 简单（1-3 功能点） | 3-5 | 5-8 | 3-5 | 2-3 |
| 中等（4-7 功能点） | 6-10 | 10-15 | 5-10 | 5-8 |
| 复杂（8+ 功能点） | 12-20 | 20-30 | 10-15 | 10-15 |

### 接口文档

| 接口复杂度 | 参数校验 | 鉴权 | 错误码 | 业务逻辑 |
|-----------|---------|------|--------|---------|
| 简单（1-5 接口） | 10-20 | 5-10 | 5-10 | 5-10 |
| 中等（6-15 接口） | 20-50 | 10-20 | 10-20 | 10-20 |
| 复杂（16+ 接口） | 50-100 | 20-40 | 20-40 | 20-40 |

## 常见问题

### Q: XMind 文件无法打开？

确保 `content.json` 使用 XMind 专用 JSON 格式（数组结构 `[]`），而非通用 JSON 对象格式 `{}`。

### Q: Excel 用例数量有限制吗？

无限制。Excel 中有多少条用例，XMind 就生成多少条（反之亦然）。

### Q: 如何确定用例优先级？

- **P0**：核心用例，基本功能验证，必须通过
- **P1**：重要用例，主要功能验证，建议通过
- **P2**：普通用例，边界情况验证，常规覆盖
- **P3**：低优先级用例，异常情况验证，可选覆盖

### Q: 如何处理自定义格式的输入？

系统会识别输入格式并尝试匹配标准结构。如果无法识别，会提示用户提供标准格式的输入。
